# OWASP ASVS 5.0 mapping (self-assessment)

This maps NexusFlow AI to the seventeen chapters of the
[OWASP Application Security Verification Standard](https://github.com/OWASP/ASVS)
**5.0.0**, with the evidence for each: the code, the tests that pin the behaviour,
and the documents that explain it.

**What this is - and is not.** It is a self-assessment made with AI assistance,
at the level of chapters and their main requirement areas. It is not a
requirement-by-requirement verification, an audit or a certification (OWASP
itself certifies nothing). Its purpose is to show a reviewer where to look, and
to state the gaps plainly. An independent assessment should verify it.

**Target level.** Level 2 - the level ASVS intends for most applications - for
the public and internal APIs, with selected Level 3 controls: field-level
encryption, a hash-chained audit trail verified daily, per-tenant network
allowlists, and an isolated sandbox for untrusted content. The gaps against
Level 2 and Level 3 are listed in the last column and summarised at the end.

Status: **Addressed** - the chapter's applicable requirement areas are
implemented and tested; **Partly** - implemented with named gaps; **N/A** - the
chapter's subject does not exist in NexusFlow.

## Gaps, in one place

| Gap | Level | Plan |
|---|---|---|
| Passkeys can be required per organization, but a session that passed TOTP or a recovery code can still register one (the recovery path); no attestation | L2-L3 | Tie registration in such organizations to a passkey session or an administrator's approval; an interop pass with real browsers and authenticators |
| Single sign-on is OpenID Connect only: no SAML, no front- or back-channel logout; not yet tested with real identity providers | Enterprise expectation | An interop pass with Okta, Microsoft Entra ID and Google Workspace; SAML if customers need it |
| No HSM; keys in process memory | L3 | Optional Vault transit wrapping protects the keys at rest and at start-up (DEPLOYMENT.md, section 8); an HSM-backed KMS would keep them out of the process |
| Malware scanning optional | Context-dependent | Enable ClamAV where tenants upload files from untrusted parties |
| No independent verification | - | Commission a penetration test and an ASVS assessment before production |
